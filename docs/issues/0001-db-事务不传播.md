# ISSUE-0001 — db 事务回调内 SQL 各自独立提交，不在同一事务

> **编号**：0001　**状态**：🟢 已修复　**严重程度**：🚨 阻断
> **发现日期**：2026-07-16　**相关任务**：db 模块（对照 `docs/java-go-comparison.md` §2.1）

## 问题描述

`Transaction` / `TransactionWithID` 只对「回调外的提交/回滚」做了包装，但回调内部通过 `db.Insert` / `Dao` 等门面发起的每条 SQL，都各自从连接池取新连接并独立自动提交，事务并未真正包裹它们。透明事务形同虚设。

## 复现步骤

1. 调用 `db.Transaction(func() error { db.Insert("t", row1); db.DeleteById("t", 2); return errors.New("force rollback") })`
2. 观察数据库

## 期望行为

回调返回 error 时，`Insert` / `Delete` 全部回滚；返回 nil 时全部一起提交——所有写操作处于同一数据库事务。

## 实际行为

`Insert` / `Delete` 各自独立提交成功；即便回调返回 error 触发 `Rollback`，此前已提交的数据不会回滚。

## 影响范围

所有使用 `db.Transaction` / `server.TxInterceptor` 的写操作；多表写入、扣减库存+落单等需要原子性的业务均受影响。

## 相关文件 / 符号

- `db/transaction.go` — `TransactionWithID` 只 `begin/commit/rollback`，未把 `*sql.Tx` 传入回调
- `db/executor.go:36` — `config.Pool().Exec` 直接取池连接，自动提交
- `server/tx_interceptor.go` — `TxInterceptor` 依赖 `Transaction` 但同样不传播连接
- 对照 Java：`aifei-db/transaction/TransactionKit.java` 用 `ThreadLocal` 绑定 `Connection`，事务内所有 `Db` 调用复用

## 建议方案

引入 context 传播事务连接：在 context 中存 `*sql.Tx`，executor 优先从 context 取连接（无则走池）；`Transaction` 把带 tx 的 context 传入回调 `fn(ctx)`。

## 解决记录

- 修复提交 / PR：（本次本地改动，未推送）
- 改动（按建议方案引入 context 传播事务连接）：
  - `db/tx_context.go`（新）：`DBConn` 接口（统一 `*sql.DB`/`*sql.Tx`）；私有 `txKey`/`withTx`（nil ctx 安全）/`txFromContext`；公开 `WithTx`/`TxFromContext`。
  - `db/config.go`：新增 `(c *Config) runner(ctx)`——ctx 有 tx 用 tx，否则池。
  - `db/dao.go`：`Dao` 加 `ctx` 字段 + `Ctx(ctx)` + `runner()`；`Dao.Transaction` 签名改 `fn(ctx, *Dao)`。
  - `db/executor.go`：13 处 `config.Pool()` → `dao.runner()`；`execTransaction` 重写——把 `*sql.Tx` 经 ctx 传播给回调，嵌套调用 join 外层事务（不另 begin/commit）。
  - `db/batch.go`：`Batch` 加 `ctx` + `Ctx(ctx)` + `runner()`，4 处取连接改用 runner。
  - `db/transaction.go`：`Transaction`/`TransactionWithID` 回调签名破坏性改 `func(ctx)`；新增 `TransactionCtx`/`TransactionCtxWithID`（嵌套 join，nil ctx 安全）；`TxBegin` 保留作手动逃逸口。
  - `db/db.go`：新增 `WithCtx(ctx)`/`NewBatchCtx(ctx)` 及 `InsertCtx`/`DeleteByIDCtx`/`FindByIDCtx` 等 ctx 版门面。
  - `http/context.go`：`HttpContext.SetContext(ctx)`（经内嵌提升覆盖 `*In` 与 `*HttpContext`）。
  - `server/tx_interceptor.go`：重写为 `db.TransactionCtx` + `setInContext`（鸭子接口 `ctxSetter`），把带 tx 的 ctx 注入请求，业务方法用 `db.Ctx(in.Context())` 即自动入事务。
  - 测试：`_example/db_sqlite_test` 改写 `TestTransaction`/`TestTransactionRollback`（后者真正 Insert 后回滚、断言 0 行）并新增 7 个（TransactionCtx/嵌套 join/Dao.Transaction/Batch/nil ctx 回退/TxBegin+WithTx 等）；新增 `server/tx_interceptor_test.go`（setInContext 注入路径）。
- 校验：`go build`（workspace 全模块）/ `go vet ./db ./http ./server` 改动文件 0 新错。
- 验收：`go test ./_example/db_sqlite_test`（含 `TestTransactionRollback` 断言回滚后 0 行——修复前为 1 行）、`./db`、`./server` 全部通过。
