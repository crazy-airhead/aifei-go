# ISSUE-0015 — db 缺少原生连接逃逸口 call / FunExecutor

> **编号**：0015　**状态**：🔴 未处理　**严重程度**：💡 体验
> **发现日期**：2026-07-16　**相关任务**：db 模块（对照 `docs/java-go-comparison.md` §2.2）

## 问题描述

Java `Dao.call(JdbcFun)` 暴露裸 `Connection`，附 `JdbcKit`（Enjoy-SQL 解析 + `ResultSet`→Row），用于存储过程、同连接多语句、临时表优化等原生 JDBC 场景。Go 无等价物；`TxBegin()` 仅返回 `*sql.Tx`，`Dao` 无 `Call` / `WithConn` 钩子。

## 期望行为

提供一处「拿到底层连接/事务，自行执行原生 SQL」的逃逸口，且能复用 Enjoy-SQL 解析与 Row 映射。

## 实际行为（Go 现状）

无 `Dao.Call` / `WithConn`；用户要执行存储过程或同连接多语句，只能在框架外另开连接，脱离事务与 Row 映射。

## 影响范围

存储过程调用、需要同连接的临时表/会话变量优化、复杂原生 SQL 场景。

## 相关文件 / 符号

- `db/executor.go` — 无 `FunExecutor` 等价
- `db/dao.go` — 无 `Call` / `WithConn`
- 对照 Java：`aifei-db/executor/FunExecutor.java`、`core/Dao.java` `call(JdbcFun)`

## 建议方案

为 `Dao` 增加 `Call(fn func(conn DBConn) error)` / `WithConn(fn)`，在事务上下文中复用 `*sql.Tx`、否则从池取连接；提供 Enjoy-SQL 解析 + `Rows`→Row 的辅助。
