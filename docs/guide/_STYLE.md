# Guide 写作规范

本文件定义 `docs/guide/` 下各模块说明文档的统一写作规范，供新增或修订文档时遵循（人与 AI 均适用）。风格标杆：[`data-isolate.md`](data-isolate.md)（~500 行：背景 → 架构 → 核心机制 → 集成 → 结构 → 总结）。

---

## 命名与位置

- 路径：`docs/guide/<slug>.md`（`<slug>` 为模块名，如 `db`、`enjoy`、`cache`、`data-isolate`）
- 语言：全中文；代码、类型名、配置键、SQL 保留英文原样
- 每个模块一篇；总索引见 [`README.md`](README.md)

## 统一模板大纲

章节顺序与数量按模块特性裁剪，但首尾必含：

```text
# Aifei-Go <模块名>：<一句话定位>
> <一句精华，加粗核心卖点>

## 1. 背景与定位
   - 是什么、解决什么问题
   - Java Aifei 对应关系（若有；本项目是 Java Aifei 的 Go 移植）
   - 零外部依赖 / 依赖哪些模块或第三方库

## 2. 核心概念 / 总体架构
   - 关键类型/接口列举（表格）
   - 架构或数据流 ASCII 图（强烈建议有）

## 3. 关键 API
   - 核心 interface / struct 定义（Go 代码块）
   - 最小可用代码示例

## 4 ~ N. 核心机制（2~4 节，每节一个机制/特性，配代码或表格）

## N. 配置 / 集成方式
   - 插件类：config.* 的 YAML 片段 + main() 注册代码
   - 库类：典型初始化 + 使用代码

## N+1. 模块结构
   - 文件清单表（文件名 → 职责一行）

## N+2. 总结
   - 3~6 条设计原则要点

### 延伸阅读
   - 链接相关 guide（相对路径，如 [db](db.md)）与 docs/arch/ 设计文档
```

## 风格规则

- 标题层级：`#` 文档标题，`##` 数字章节，`###` 子节；章节间用 `---` 分隔
- 多用**表格**做对比/清单；多用**代码块**（Go / YAML / SQL / 纯文本 ASCII 图）
- 信息密度高，避免空话；API 名、类型名用反引号
- **交叉链接**：提到其他模块时链到同目录对应文档（相对路径 `<slug>.md`，如 `[db](db.md)`）；设计文档用 `../arch/<file>.md`

## 内容来源（必须实际读取，不得凭记忆编造）

1. **模块源码 `.go` 文件** —— 真实 API、类型签名、行为
2. **`CLAUDE.md`** 的 Architecture / 模块结构章节 —— 但需核对，CLAUDE.md 偶有与源码不符之处（以源码为准）
3. **[`data-isolate.md`](data-isolate.md)** —— 风格范例
4. `docs/arch/` 下相关设计文档（若存在，用 `grep`/`find` 确认）

## 质量红线

- 代码示例的类型名/方法签名/配置键**必须与源码一致**，逐项核实；不确定就去读源码
- **不得编造**不存在的 API、配置项、文件
- 篇幅 300~500 行（特性面广的模块可适当放宽）；文件以单个换行结尾
- 完成后用 `wc -l` 自查行数，用 `grep -nE "^#{1,3} "` 自查标题结构
